# Game Factory

Монорепозиторий веб-игр для Яндекс Игр (дальше — другие порталы через Playgama).
Цель — поток игр, где каждая следующая лучше предыдущей. Не рескины: у каждой игры своя механика или поворот.

## Стек
Phaser 4 + TypeScript + Vite. Node ≥ 20. Тесты: Vitest (юнит), Playwright (браузер, десктоп + телефон).
Знания — Markdown-скиллы в `.claude/skills/`. Никаких БД и RAG.

## Устройство
```
engine/       общий код: platform (Yandex SDK / mock), i18n, save, ads, audio, ui
templates/    жанровые каркасы; сейчас только blank (заглушка)
art/<id>/     стиль и ассеты до разработки: STYLE.md, boards/, assets/, CREDITS.md
games/<id>/   игра = game.config.ts + content/ + src/ + assets/ + CONCEPT.md + STYLE.md
pipeline/     run (dev/build), new-game, audit, pack, serve, art/ (generate.py — ComfyUI, unify.py — сведение стиля)
tests/        unit/ (vitest), e2e/ (playwright, смоук прогоняет ВСЕ сборки из dist/)
knowledge/    ideas.md (реестр идей и статусов), market/, concepts/, postmortems/, moderation-log.md
prompts/      промпты для расписаний (ежедневный скан трендов)
```

## Команды
```
npm run dev -- <id>            dev-сервер (?lang=en, ?mock)
npm run ideas                  реестр идей по статусам (-- --check проверка, -- next следующий номер)
npm run new-game -- <id>       новая игра из одобренного концепта (templates/blank)
npm run build -- <id>          сборка в dist/<id> (--target playgama|crazygames → dist/<id>--<цель>, --target all)
npm run audit -- <id>          линтер требований площадки (после build, тот же --target)
npm run pack -- <id>           build + audit + zip в release/<id>/ (--target playgama|crazygames|all)
npm run check                  всё, что гоняет CI: typecheck, unit, build:all, audit, e2e
```
В облачной сессии Playwright запускать с `PW_CHROMIUM_PATH=/opt/pw-browsers/chromium`.

## Путь игры
```
скан трендов → идея №1 → человек выбирает → концепт → человек одобряет → стиль → человек выбирает → ассеты → человек принимает → разработка → выпуск
```
Статусы: идея → концепт → одобрен → стиль одобрен → ассеты одобрены → в разработке → выпущена (или отклонена / отложена). Единственный источник —
`knowledge/ideas.md`, формат проверяет `npm run ideas -- --check`.
- Ежедневный скан (`market-scan`) добавляет идеи со статусом «идея» и постоянными номерами. Концепты сам не пишет.
- Концепт (`concept`) пишется только по идеям, которые назвал человек.
- Концепт утверждает все механики и системы. Игры насыщенные: основная механика + поворот + дополнительные системы, как у трендов.
- Стиль (`art-style`) и ассеты (`assets`) — после одобрения концепта, каждый утверждает человек.
- Разработка (`new-game`) — только при статусе «ассеты одобрены». Одобряет только человек.

## Жёсткие правила
1. Игра общается с площадкой только через `@engine/platform`. Никаких `YaGames`/`ysdk`/`bridge.*`/`CrazyGames.SDK` в `games/`.
   Площадку выбирает цель сборки: `yandex` (Yandex SDK), `playgama` (Playgama Bridge) или `crazygames` (CrazyGames SDK v3); код игры один.
2. `platform.gameReady()` — один раз, когда игра реально готова. `gameplayStart()/gameplayStop()` — на каждый вход/выход из активной игры (меню, пауза, конец уровня, реклама).
3. Межстраничная реклама — только через `ads.interstitial()` в естественных паузах. Rewarded — только по явной кнопке с понятной наградой. Во время рекламы игра на паузе и без звука.
4. Все тексты — через i18n, RU обязателен, EN рядом с теми же ключами. Никакого текста в коде сцен.
5. Сохранения — через `SaveStore`, не через localStorage напрямую.
6. Пути в сборке относительные (`base: './'`), без внешних CDN, шрифтов и скриптов. Исключение — SDK площадки, который она требует грузить со своего адреса (`/sdk.js` Яндекса, `sdk.crazygames.com`).
7. Никакого ИИ внутри игры (правило Яндекса 1.23). Claude делает игру, но не работает в ней.
   Картинки для игры — только бесплатными средствами с коммерческой лицензией: FLUX.2 klein 4B на ноутбуке человека,
   бесплатные паки, Gemini вручную. Платные тарифы не использовать. Каждый файл ассетов — в `CREDITS.md`.
8. **Никогда не отключать, не пропускать и не ослаблять тест ради зелёного CI.** Чинить причину.
9. Изменение в `engine/` должно проходить `npm run check` для всех игр и шаблонов.
10. Одна игра — одна ветка `game/<id>` и один тред. Не трогать чужие `games/<id>` в той же ветке.

## Что решает человек
По каким идеям писать концепт, какой концепт одобрить, «интересно ли», промо-материалы, отправка на модерацию, публикация.
Claude готовит варианты и чек-листы, но эти шаги не делает сам.

## Скиллы (подгружай по задаче)
- `yandex-moderation` — требования и прошлые отказы. Перед любым релизом.
- `platform-sdk` — как пользоваться engine/platform, рекламой, сохранениями; сборка под Playgama и её отличия.
- `concept` — концепт по выбранной идее и решение человека.
- `art-style` — три доски стиля после одобрения концепта, выбор человека, `art/<id>/STYLE.md`.
- `assets` — полный набор ассетов в утверждённом стиле: генерация на ноутбуке, паки, сведение, лицензии.
- `new-game` — от одобренных ассетов до первого играбельного билда.
- `release-pack` — zip, медиа и тексты для каталога.
- `promo-media` — иконки, обложки, скриншоты, видео.
- `market-scan` — ежедневный скан, идеи в реестр и недельная сводка трендов.
- `extract-template` — вынести удачную игру в шаблон.
- `postmortem` — разбор игры через 3 недели.
- `learn` — как записывать новые знания в скиллы.

## Обучение фабрики
После каждого отказа модерации → запись в `knowledge/moderation-log.md` + пункт в `yandex-moderation` + проверка в `pipeline/audit.mjs`, если её можно автоматизировать.
После каждого релиза и постмортема → вывод в соответствующий скилл (см. `learn`).
Шаблон для нового скилла: `knowledge/templates/SKILL.template.md`.

## Стиль кода
TypeScript strict. Сцены короткие, логика игры отдельно от Phaser, где её можно юнит-тестировать.
Константы баланса — в `game.config.ts`. Комментарии в коде на английском, документация на русском.
Коммиты: `<область>: что сделано` (например `engine: debounce saves`, `games/merge-cats: level 5`).
